# Simitone.Touch - the on-screen control system

A self contained module that puts a virtual gamepad on the screen of a touch
device and turns the fingers into the keys the engine already understands.

The module has **no dependency on FreeSO, on Simitone.Client or on any game
logic**. It only knows about MonoGame primitives, which means it can be tested,
themed and reused on its own.

```
Simitone.Touch/
├── TouchAction.cs              # what a control can do + the keys it produces
├── TouchWidgetLayout.cs        # where a control is placed (relative units)
├── TouchControlSettings.cs     # global settings + the serialisable profile
├── TouchControlTheme.cs        # colours and metrics of the controls
├── TouchControlService.cs      # the facade: capture, gestures, keys, drawing
├── TouchControlProfileStore.cs # JSON profiles on disk
├── TouchTextRenderer.cs        # font abstraction (the host plugs its font in)
├── Input/
│   ├── ITouchInputBackend.cs   # touch + haptic abstractions
│   └── MonoGameTouchBackend.cs # the MonoGame implementation
├── Icons/TouchIconProvider.cs  # embedded icons + user overrides
├── Widgets/
│   ├── TouchPrimitives.cs      # runtime generated circle/ring textures
│   ├── TouchWidget.cs          # base class + the drawing context
│   ├── TouchButton.cs          # round button (hold / tap / toggle)
│   ├── TouchJoystick.cs        # floating thumb stick
│   └── TouchControlFactory.cs  # the default layout
├── Editor/TouchLayoutEditor.cs # drag, resize, profiles, grid snap
└── Resources/TouchIcons/       # 26 real icons (256 px, white line art)
```

## How it works

Every frame the service

1. asks the backend for the current fingers,
2. gives the fingers that are not used by a control to the gesture recogniser
   (pinch = zoom, two finger rotation = rotate, drag = pan),
3. hands the remaining fingers to the widgets (a widget captures the finger
   that pressed it and owns it until it is lifted),
4. collects the actions that are currently held and turns them into a list of
   `Keys`,
5. draws the overlay with its own sprite batch.

The host only has to do two things:

```csharp
// every frame, before the game reads the input:
state.KeyboardState = new KeyboardState(touch.GetVirtualKeys());

// every frame, while drawing:
touch.Draw();
```

The fingers that were used by a control are removed from `UpdateState.MouseStates`
by the bridge, so the game never sees them.

## The actions

`TouchAction` describes everything a control can do. Most of the actions are
mapped to the keys the engine uses anyway:

| Action | Keys |
|--------|------|
| Move forward / back / left / right | `W`/`Up`, `S`/`Down`, `A`/`Left`, `D`/`Right` |
| Zoom in / out | `OemPlus` / `OemMinus` |
| Rotate left / right | `OemComma` / `OemPeriod` |
| Pause / resume | `P` |
| Speed 1x / 3x / 10x | `D1` / `D2` / `D3` |
| Single frame | `D0` |
| Cancel | `Escape` |

The remaining actions (mode switches, options, inventory, ...) have no keyboard
equivalent and are reported through the `ActionTriggered` event. The bridge in
`Simitone.Client` decides what they mean.

## The layout

A control is placed with a `TouchWidgetLayout`: an anchor (one of the four
corners), two relative offsets, a relative width and height, an opacity and a
visibility flag. The layout is resolved against the size of the screen, so the
same profile works on a phone and on a tablet.

## The layout editor

The editor is drawn by the module itself and therefore works on every screen of
the game. While it is open every control gets an outline, the selected one gets
a resize handle, and a toolbar at the top offers

* `Done` - leaves the editor and stores the layout,
* `Grid` - toggles the grid snap,
* `Opacity -` / `Opacity +` - the opacity of the whole overlay,
* `Layouts` - the profile browser (load, save, delete),
* `Hide` / `Show`, `Size -` / `Size +` - for the selected control.

## Icons

The 26 icons are real 256 px line drawings, they are generated by
`Resources/TouchIcons/generate_icons.py` (needs Pillow) and embedded into the
assembly. Users can replace them by dropping a `<name>.png` into the icon
folder of the user directory.

## Profiles

A profile is a JSON file:

```json
{
  "Name": "Default",
  "Settings": { "Opacity": 0.85, "Scale": 1.0, "PinchToZoom": true, ... },
  "Widgets": { "camera_stick": { "Anchor": 0, "OffsetX": 0.025, ... } },
  "Order": ["camera_stick", "zoom_in", ...]
}
```

They are stored in `<UserDir>/touch/` (the user directory of the engine), so
they survive an update of the app and can be copied to another device.
